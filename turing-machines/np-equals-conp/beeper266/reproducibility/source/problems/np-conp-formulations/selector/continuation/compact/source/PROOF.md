# Certificate-tape source theorem

## Scope, convention, and authorship

This proof concerns the new source `certificate_popfirst_power.py`. Its source
and full producer identities are recorded by the complete-build metadata and
the source-fixture report. It is a new construction, not a recovered historical
implementation. The source author also authored the source experiments and accompanying
fixtures. Those fixtures and this proof are
author evidence; independent review and physical compilation are separate.

The theorem is that the source runs forever, and emits finitely many `beep()`
events if and only if NP = coNP. Every acceptance call and every incorrect
candidate stage finishes in finite time. Candidate indices, input lengths,
certificate lengths, clocks, exponents, and arithmetic values are unbounded.
The event is the source `beep()`; a complete physical producer must preserve
its finite/infinite behavior with an explicitly designated transition event.
No physical-halting criterion or arbitrary finitely visited state is used.

The change replaces per-step nondeterministic choices by a certificate on the
simulated negative half-tape. Every certificate is generated by the counted
source program, not supplied to the physical blank-start machine. The physical
machine still starts with an entirely blank binary tape.

## 1. Deterministic relative-machine descriptions

For a natural description e, read its finite binary expansion low bit first,
followed by infinitely many zero bits. Split it into unary records `1^a 0`,
numbered from zero. A configuration consists of a natural state address s, a
binary finite-support tape, a head h, and a facing f in {-1,+1}. The initial
state is 1, the initial head is zero, and the initial facing is +1. State zero
is accepting and absorbing. For a positive state s scanning bit z, take record

    r = s + z - 1.

This index is nonnegative. If that record has value a, let

    write = a mod 2,
    turn = floor(a/2) mod 2,
    next = floor(a/4).

Write `write`, set f' = (-1)^turn f, move to h+f', and enter `next`.
All descriptions have total semantics. A missing record has value zero. An
unfinished final run of ones ends at the first virtual zero. If ell is the
bit length of e, all field values are at most ell and all next state addresses
are at most floor(ell/4). Including both facings therefore gives a finite
ordinary deterministic machine. Unaligned addresses cause overlapping row
windows, with no ambiguity or undefined transition.

For k positive logical states, encode logical q>0 by s(q)=2q-1 and logical
acceptance by zero. Its two records have indices 2(q-1), 2(q-1)+1. Encode the
row `(write,turn,target)` as

    1^(write + 2*turn + 4*s(target)) 0.

The complete 2k-record prefix has length L<=16k^2, because each record has
length at most 8k. Every used row ends inside that prefix and returns to its
finite encoded state set. If e0 is the integer represented by that fixed-length
prefix, then every e=e0+2^L Q, Q>=0, describes exactly the same reachable
machine on every tape and every clock. This supplies arbitrarily large integer
descriptions without changing behavior or running time.

An ordinary binary deterministic single-tape machine with left/right moves is
converted to this model just by duplicating positive control states by facing.
An absolute move d from a state whose facing is f uses turn zero if d=f and
one otherwise, and enters the target copy whose facing is d. Acceptance goes
to address zero. Start in the +1 copy. This adds no simulated steps and at
most doubles the control. Finite-alphabet encoding and stay-move removal have
the usual fixed polynomial simulation overhead, which is included in the
clock bounds below. No nondeterministic forced-write normalization is needed.

## 2. Bounded certificate acceptance and the exact source invariant

For a natural initial tape integer x, its low-to-high bits occupy cells
0,1,2,... . A certificate b has its low-to-high bits in cells -1,-2,-3,... .
All other cells are zero. Let A(e,x,C) mean that some b<2^C causes the described
deterministic machine to enter state zero within C transitions on this tape.

The source first starts `branch` at 1 and doubles it exactly C times, using
the positive countdown `steps`. Thus it obtains 2^C in finite time, including
2^0=1. The outer positive-countdown loop decrements `branch` before each
attempt. It consequently tries each certificate exactly once, in descending
order 2^C-1,...,0, and then exits. This is a finite source computation for every
finite C. No host precomputation or uncounted initial tape implements this bound.

At the start of an attempt, `left=branch`, `right=initial`, `state=1`, and
`steps=C`. At every positive-state transition boundary, the low bits of
`right` are the current scanned cell and successive cells in direction f;
the low bits of `left` are the cells h-f,h-2f,... . Popping
`read,right=right%2,right//2` separates the current cell from its forward tail.
The source then sets `place=state+read=r+1`. Each positive `place` iteration
decrements the counter and pops one complete unary record. The final record
value is therefore exactly a_r. Two quotient/remainder pairs obtain its write
bit, turn bit, and next state.

If the turn bit is one, exchanging the two tails changes their orientation.
The assignment `left=2*left+write` puts the written old head behind the new
head. The remaining `right` is already the new head followed by its forward
tail, so no second scanned-bit pop is needed at the loop end. This is exactly
the described transition. For state zero the guard omits all subsequent tape
and decoder operations, giving absorbing acceptance. The clock is decremented
once on every iteration, including after acceptance.

After C iterations the source accepts precisely when the state is zero. For
C=0 no simulated transition occurs, state remains 1, the single certificate
attempt fails, and the call returns zero. Each record pop terminates: an odd
positive digit strictly decreases under halving and the zero tail ends the
run immediately. The place and clock counters strictly decrease around finite
bodies. Both the bound-generation loop and the certificate countdown are
finite. Thus `accept(e,x,C)` returns exactly A(e,x,C) for every natural triple,
including arbitrary malformed or truncated descriptions.

A C-step computation starting at zero cannot inspect any certificate cell
beyond distance C. Therefore this finite certificate enumeration includes every
certificate prefix that could affect a C-step execution, even if a conventional
verifier is described using an infinite padded certificate tape.

## 3. A fixed NP-complete reference language

For a raw word Y of length n and low-bit integer y, define

    K = {Y : A(2^n+y, 0, n)}.

Every raw word has a meaning. The empty word is not in K, because the clock is
zero. The high sentinel bit fixes the description's raw length.

K is in NP: guess n certificate bits and simulate n described transitions.
The program has n+1 bits, every reachable address is O(n+1), and every selected
record can be located by scanning the actual program and O(n+1) virtual zero
records. The visited tape lies in [-n,n]. Ordinary binary arithmetic and tape
representations give a polynomial-time verification procedure. This complexity
argument concerns membership in NP; it does not assert that the counted unary
physical simulator runs in polynomial time.

For NP hardness, fix any language L0 in NP. Use a deterministic binary verifier
V with a known polynomial time guard, a polynomial certificate prefix, and a
permanent rejecting sink after its guard. Its input is the self-delimiting
right-tape word E(x)=1^b 0 x and its certificate lies reflected on the negative
half-tape. This is an ordinary polynomial-time verifier convention: a standard
finite certificate can be padded to its known polynomial length; the verifier
reads at most that length, and ordinary tape copying/encoding incurs polynomial
overhead. The verifier is sound for every certificate, not just correctly
formatted witnesses.

For each b-bit input x, construct a deterministic blank-right-tape machine D_x.
An O(b+1)-state writer prints E(x), returns to head zero without altering the
negative certificate cells, and starts V. Time-layer its finite control up to
the known polynomial bound for length b, so all branches become a permanent
rejecting sink after that bound. Here there is only one deterministic execution
per certificate. The construction size, writer time, and guarded verification
time are polynomial in b. D_x accepts some certificate if and only if x is in
L0, and no certificate can create a first acceptance after the inner guard.

Translate absolute moves into relative moves by facing duplication and encode
the complete aligned prefix of length Lx. Let T(b) bound the writer, return,
and guarded successful verification, and let p(b) bound the certificate prefix
used. Choose n>=max(Lx,T(b),p(b)), with this maximum polynomial in b, and pad
the encoded prefix with zeros to raw length n. The external sentinel bit lies
past every used record. An accepting certificate can be padded to n bits, and
any n-bit certificate is subject to V's soundness and inner guard. Therefore
the resulting Y_x belongs to K exactly when x belongs to L0. This is a
polynomial many-one reduction. K is NP-complete and its complement is
coNP-complete.

## 4. Polynomial candidates and the coupled integer exponent

Candidate j accepts a raw word Y of length n exactly when

    A(j, E(Y), (n+1)^j).

For each fixed j this language is in NP: the machine is finite and deterministic,
its guessed certificate has polynomial length (n+1)^j, its encoded input has
length 2n+1, and its clock is polynomial in n. A correct candidate accepts
exactly the complement of K on every raw Y. Existence therefore implies that
the complement of K belongs to NP.

Conversely assume the complement of K is in NP and take a deterministic verifier
V with a polynomial certificate prefix and guarded polynomial runtime under
the same tape convention. Add this wrapper in the ordinary absolute-direction
machine, before facing duplication:

* Reading zero in the wrapper's start state enters acceptance in one step.
  On valid E(Y), this is precisely the empty input, which belongs to the
  complement of K and has candidate clock (0+1)^j=1.
* Reading one preserves it, moves right, and enters a relay. The relay preserves
  whichever symbol it reads, moves left, and enters V's start state.

For every nonempty input the two-step wrapper restores the exact tape and head
and never inspects or changes the certificate. After orientation translation
the relay enters the facing -1 copy of V's start, so its future absolute moves
are correct. The one-step empty acceptance may alter a tape cell because the
machine has already accepted; this has no effect on acceptance.

Choose C0>=1 and d so that both successful runtime including the wrapper and
the certificate-prefix requirement are at most C0(n+1)^d for every n>=1.
Every integer j>=d+ceil(log2 C0) then has enough clock and enough certificate
bits. Complete-prefix padding supplies an arbitrarily large j describing the
same wrapped verifier. Select one beyond this threshold. The internal guard
ensures that a longer outer clock cannot create a spurious acceptance, and
certificate soundness holds for every longer padded certificate. Thus j is
correct on all nonempty words and on the empty word.

A correct candidate exists exactly when the complement of K is in NP, which
is equivalent to NP=coNP: coNP-completeness and closure under polynomial
reductions yield coNP subset NP, and taking complements yields the reverse
inclusion. This uses neither the P=NP lane's theorem nor equiconsistency.

## 5. Exhaustion, finite counterexamples, and the beeping polarity

The main controller is unchanged from the reviewed source. At a comparison,

    candidate = 2^n,
    candidate <= i < 2*candidate,
    initial = candidate-1 + 2*candidate*(i-candidate).

Consequently i=2^n+y and `initial` is exactly the integer for E(Y)=1^n 0 Y.
The controller enumerates all y of length n, then increments n, with no bound.
Its equality test is a complement error: reference=1,candidate=1 violates
soundness, while reference=0,candidate=0 violates completeness. A recognizer
that rejects everything is defeated by the empty word. Every incorrect
candidate differs on some finite raw word, and its least such comparison is
reached after finitely many terminating calls. It cannot wait forever inside
one false verification step.

The outer loop starts with `beep()` and tests candidates j=0,1,2,... in order.
If a least correct candidate j* exists, every smaller candidate is rejected in
finite time. The machine emits the event for j*, then keeps checking inputs
forever without another event. There are exactly j*+1 source events. If no
correct candidate exists, each candidate is rejected in finite time and the
events continue infinitely. In either case the source never terminates.
Thus finite beeping is equivalent to NP=coNP with the required polarity.

## 6. What tests and physical compilation must establish

Finite fixtures check record selection, dense-versus-sparse tape semantics,
both turn directions, descending certificate enumeration, zero and boundary
clocks, delayed acceptance, arbitrary encodings, complete-prefix padding,
orientation translation, the empty-input wrapper, and source-to-grammar values.
Controlled candidate fixtures exercise unsound and incomplete rejection, delayed
counterexamples, and stabilization. They do not decide NP versus coNP or prove
eventual silence from a bounded physical run.

The compiler must preserve natural arithmetic, finite positive-countdown loops,
tuple capture and scratch contracts, calls/returns, and source event order.
Every primitive finite operation must finish in finitely many physical steps;
the certificate enumeration is huge but finite. A complete table must pay for
the doubled bound, program, decoder, tape simulation, candidate enumeration,
initialization, event adaptation, and totalization. The accompanying composition
and exact-byte physical reviews carry these separate obligations. No
proof-assistant certification or global state minimum is claimed here.
